# tests/

Tests, run by `pytest` inside the image that `make image` builds and `make test` runs, never against a toolchain on the author's machine.
A test here checks a property that could be wrong: byte-exactness where the bytes are stable, and a declared tolerance where they are not. A test that fails for a reason nobody cares about is a defect in the test, not a finding, and `quality/REF-013` decision 2 says why that rule exists.
Every input a test uses is generated by the test, from constants the test states, or is a manifest in the tree the test holds the code to, so that what a test asserts can be read without opening a data directory.
Of the twelve modules under `implementation/library/`, two are held by a test here, `manifest_verify` and `matching`, and `test_iso_extract.py` drives the binary built from `implementation/tools/iso-extract.c`; the other ten have no test. That is a deferral, not a decision: commit 8fb8443 checked the measurement modules by re-running the records they produced and said whether they get tests should be decided rather than smuggled in, and no refinement and no issue has decided it since.
Not here: a corpus image, a minutia, a template, a fixture that reaches outside the tree, or a test whose failure would be uninteresting.
