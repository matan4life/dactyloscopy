# scripts/

Scripts run from the command line: the command form of each measurement instrument, of the matching run and of its reproduction, and two checks, `verify_manifests.sh` and `check_tools.sh`, that hold every manifest and the tools in the image to what the manifests declare.
A script here may start a run - `run_matching.sh` is what `make run-matching` invokes - but it holds no mechanism. Nothing in this directory computes a number that a result depends on; the code that does belongs under `implementation/`, and a script only reaches it.
A script may be the command form of a module under `implementation/`, in which case it imports and calls and does nothing else, so that a run and a person reach the same code by the same path. The five `measure_*.sh`, `run_matching.sh` and `reproduce_matching.sh` are that shape; `verify_manifests.sh` imports and calls and then formats the report in the script, which `docs/manifests.md` records as a finding not acted on; `check_tools.sh` carries its checks in the script, driven by `manifests/MAN-tools.v2.json` rather than by a module; `record_run.sh` runs on the host after `make run-matching`, places a finished record under `runs/` at the id `quality/REF-016` gives it, prints the trailers of its `run:` commit, and refuses a record that is provisional, was made at a revision other than `HEAD`, or does not digest to its observation.
Not here: experiment logic, metric code, or anything a result depends on.
