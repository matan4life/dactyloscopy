# REF-015 — An investigation's aggregate is derived data

Date: 2026-09-21
Rests on: `quality/INV-014-extractor-difference.md`,
`quality/INV-015-deformation-model.md` and
`quality/INV-016-extractor-noise-floor.md`, for what each says about where its
aggregate went. `REF-016` Decision 1 draws the line this refinement stands on
the other side of. Every factual claim below is a reference to one of those
records. This refinement measures nothing and states no fact of its own.

## Numbering

This refinement takes 015, the next free number. The gaps at 001 and 004 are
explained in `REF-002` and `REF-006`.

## Why this refinement exists

Three investigations computed a machine-readable aggregate and wrote every
number they report from it. Each says where it went: `INV-014`, "the only
thing written to the mounted output directory is the aggregate JSON this
record is made from" (The biometric rule); `INV-015`, "`$SP` is a scratch
directory outside the tree, `$SP/out` the only writable one" (Reproducing
this); `INV-016`, the same mount in its reproducing command. None says what
the aggregate is, under which of the tree's contracts it falls, or where it
should live, and none of the three contracts that could apply names it:
`runs/README.md` is written for a run's `results.json`, `quality/README.md`
excludes run records and code, and `workflow/README.md` is written for
derived data and holds only its own README. The aggregates were written to a
scratch directory, and a scratch directory is where they were when the
records were committed.

`INV-017` then made a run and `REF-016` Decision 1 says what a run is: the
scoring of a comparison list. An investigation's aggregate is not that. This
refinement says what it is instead.

## Decision 1 — an investigation's aggregate is derived data

**A machine-readable aggregate an investigation computes is derived data in
the sense of `workflow/README.md`: produced from raw inputs by a rule, from a
manifest and a code revision, regenerable rather than trusted. It is never
committed. It lives under `$LABDATA/derived/<investigation>/<subset>/`, and
`workflow/` carries one rule per instrument saying how it is produced.**

The ground is the three records' own description of what they wrote and
where, and `workflow/README.md`'s definition, which they match clause for
clause: each aggregate is produced from the corpus mounted read-only, depends
on `MAN-fvc2002.v1` and `MAN-tools.v2` and the revision each record names, and
is regenerated by the command form each record now names — `INV-015` and
`INV-016` say their aggregate comes back byte for byte. `docs/data.md` and
`.env.example` state the same rule for `LAB_DERIVED`, and `experiments/`,
`manifests/` and `workflow/` each exclude derived artifacts by name.

## Decision 2 — the record names the aggregate's digest

**An investigation written from an aggregate names, under "Reproducing this",
the aggregate's path relative to `$LABDATA/derived`, its sha256 and its byte
count, as `INV-017` names its observation.** A record that says its numbers
come from a file a reader cannot obtain has to at least say which file, so
that a reader who regenerates it can tell whether they regenerated it.
`INV-014`, `INV-015` and `INV-016` were written before this rule and name no
digest; the paragraphs their reproducing sections gained on 2026-09-09 name
the command that returns the aggregate and that it returns the same bytes,
which is the check this decision makes routine.

## Decision 3 — the command form writes to the derived location by default

**A command form under `scripts/` that produces an aggregate writes it under
`$LABDATA/derived/<investigation>/<subset>/` unless told otherwise, and
addresses the subset by its manifest id.** `scripts/run_matching.sh` already
does both; the five `measure_*.sh` forms take a directory path and an
arbitrary output path, which is how their aggregates came to be written to a
scratch directory. Bringing them to the same form is code and follows this
refinement.

## Rejected

- **Committing the aggregates into `runs/`.** They are not runs (`REF-016`
  Decision 1) and `runs/README.md` is written for a pair list and a score
  vector. Committing them would also put into the tree artifacts that
  regenerate from what the tree already holds, in the times their records
  state.
- **Leaving them where they are.** A scratch directory is what a record may
  not rest on: it is not named, not digested and not regenerable from the
  tree. The three records stand only because their instruments are in the
  tree and were shown to return the same bytes.
- **A new directory for them inside the tree.** Every directory contract in
  the tree excludes derived data by name; a fourth contract admitting it
  would contradict three.

## Open

- ⟨OPEN⟩ The form of a rule in `workflow/`. The README says what a rule
  states and no rule exists yet; the first one written sets the form.
- ⟨OPEN⟩ Whether `INV-014`, `INV-015` and `INV-016` are amended to name a

  regenerates the file. A digest named now would be of a file regenerated
  today, not of the file the record was written from.
